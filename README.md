# АльфаНавигатор

Прототип Telegram-помощника для кейса «Альфа-Курс». Он отвечает по проверенным
фрагментам статей, показывает источник ответа и предлагает материал по теме.
Профиль консультации хранится отдельно для каждого Telegram-пользователя.

Рабочий сценарий и критерии проверки описаны в [ROADMAP.md](ROADMAP.md).
Прототип ещё не завершён: основные сценарии реализованы, статьи и один выпуск
подкаста проверены, но остаются живые проверки повторных напоминаний и запуска
незнакомым проверяющим. Ниже указано, что уже можно запустить и проверить.

## Запуск через Docker

Нужны Docker Compose, доступная Docker видеокарта NVIDIA с поддержкой GPU,
место для модели размером 5,63 ГБ и токен тестового
бота из [BotFather](https://core.telegram.org/bots#how-do-i-create-a-bot).
Бот должен работать через polling; активный webhook мешает запуску.

Закреплённый GGUF совпадает по SHA-256 с файлом из
[репозитория автора модели](https://huggingface.co/HauhauCS/Qwen3.5-9B-Uncensored-HauhauCS-Aggressive/blob/main/Qwen3.5-9B-Uncensored-HauhauCS-Aggressive-Q4_K_M.gguf).
Файлы модели в Git не входят. Compose скачивает файл, сверяет размер и SHA-256,
создаёт и загружает модель в отдельной Ollama, затем запускает приложение.
Загрузка модели в GPU может занять больше минуты; приложение ожидает её
завершения. Ollama удерживает модель в памяти между вопросами. Для создания
нужны место под исходный файл и под копию модели в Ollama. Проверка полного
скачивания на чистом Docker-хосте ещё не проведена; локально модель была
создана из уже проверенного GGUF.

1. Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN`. Не добавляйте `.env`
   в репозиторий или архив сдачи.
2. Из корня проекта выполните одну команду:

   ```sh
   docker compose up --build
   ```

Compose запускает один процесс приложения и отдельную локальную Ollama.
Digest созданной Docker-модели закреплён в `compose.yaml` и проверяется перед
каждым запросом. HTTP API доступен только на `http://127.0.0.1:8000`;
Telegram получает ответы через polling.

Ответы в Telegram используют безопасные entity-объекты aiogram: кликабельные
метки источников, сворачиваемый список подтверждений, управляемый большой
preview и кнопку следующего материала. Для заголовков подключены custom emoji
кота и Альфа-Банка из пака `AAAAAAAMOJI`. Telegram разрешает их боту, когда
владелец токена имеет Premium; при отказе API бот автоматически повторяет
сообщение с обычными `😸` и `❤️`, поэтому оформление не блокирует ответ.
Перед AI-запросом бот отправляет `⌛ Думаю…` с custom loading-emoji и редактирует
это же сообщение в ответ. Если запрос отменён новым сообщением, индикатор
удаляется. Внутренние метки фрагментов `S1`, `S2` пользователю не показываются:
в тексте используются понятные ссылки `(источник ↗)`, а одинаковые документы
объединяются в нумерованный раскрываемый список.

Исходная PostgreSQL-выгрузка для запуска не нужна. В образ входят
`assets/reviewed_articles.jsonl` — 133 фрагмента 21 публичной статьи — и
`assets/reviewed_podcasts.json` — 12 вручную прослушанных фрагментов выпуска
«Сервис в малом бизнесе». Подкастный файл закреплён SHA-256
`3df378f54466076cb9a317b62e7385074161046e9a04e50271d32c9ec7ad106c`.
Непроверенная ASR-расшифровка и аудио в образ не входят. Каталог из 18 карточек
материалов также проверяется по контрольной сумме.

Остановка: `Ctrl+C`, затем `docker compose down`. Docker volumes сохраняют
SQLite-историю и модель. Для удаления истории нужен
отдельный осознанный шаг; обычная остановка его не удаляет.

## Проверка текущего прототипа

- `GET http://127.0.0.1:8000/health` проверяет жизнеспособность процесса и
  сообщает состояние polling. `GET http://127.0.0.1:8000/ready` проверяет
  polling, исполнитель напоминаний, корпус и digest локальной модели. Когда
  Ollama недоступна, `/ready` возвращает 503 без пользовательского запроса.
- С тестового Telegram-аккаунта задайте вопрос по статье, например:
  «Какой принтер этикеток выбрать для длительного хранения товара на Ozon?»
  Проверьте ответ, ссылку на статью и рекомендацию отдельно.
- Спросите факт, которого нет в проверенном корпусе, например точную стоимость
  доставки за город. Ответ должен прямо обозначить недостаток сведений.
- Попросите бесплатный или платный курс по УСН на маркетплейсах. Карточка должна
  показывать тип доступа, краткую пользу и ссылку из проверенного каталога.
- Попросите напомнить об учёбе: укажите событие, дату, время и часовой пояс IANA
  (например, `Europe/Moscow`). Бот покажет параметры и сохранит задание только
  после ответа «да». Команда `/reminders` показывает номера. Можно попросить
  «Измени напоминание #номер, повторяй ежедневно» или «Отмени напоминание #номер»;
  эти действия тоже требуют подтверждения.
- Для налогового напоминания бот уточняет режим и просит указанную пользователем
  дату; нормативный срок по отсутствующим в базе данным он не назначает.

Локальный HTTP-прогон вопроса по базе, честного отказа и рекомендации курса
прошёл на хостовой модели и в Docker. Docker-бот подключается к Telegram через
polling; для проверки нужен свой тестовый токен.

S6 по проверенному выпуску прошёл: runtime-поиск с названием выпуска нашёл
нужный интервал у 9/9 настроечных и 3/3 отложенных вопросов; локальная Docker-
модель дала 9/9 и 3/3 ответов с правильным выпуском, таймкодом и обязательным
смыслом.

Независимый holdout из 30 новых вопросов дал 25/30 по строгому критерию и
28/30 по статусу и обязательным документам; все 7 отказов и уточнений прошли.

## Архитектура и границы данных

```text
Telegram → aiogram → диалог и SQLite-профиль → AIService
                                          ├→ проверенный корпус → поиск → локальная Ollama
                                          ├→ проверенный каталог карточек
                                          └→ подтверждение → SQLite → планировщик → Telegram
HTTP API → FastAPI ───────────────────────┘
```

`alfalearn/` содержит HTTP API, Telegram-обработчики, историю и исполнитель
напоминаний. `src/alfa_ai/`
содержит поиск, отбор подтверждений, рекомендации, разбор диалога и запрос к
модели. Модель выбирает короткие дословные цитаты; приложение проверяет их
наличие в допущенных фрагментах и само добавляет исходный текст и URL. Если
доказательство не проходит проверку, сервис не выдаёт неподтверждённый ответ.
Платные материалы представлены публичной карточкой; полный текст платных
уроков в модель не передаётся.

Исходная PostgreSQL-выгрузка не входит в рабочее дерево и Docker-контекст.
Если репозиторий когда-либо публикуется, его историю нужно отдельно проверить
на прежние версии выгрузки.

## Основные переменные

### Локальные события и обратная связь

Под ответом по базе есть кнопки «Полезно» и «Не помогло». Повторное нажатие
того же trace ID учитывается один раз. `ANALYTICS_PATH` хранит только тип
события, непрозрачный ключ операции и время; в таблице нет текста вопроса,
username или Telegram chat ID. `ANALYTICS_RETENTION_DAYS` задаёт срок очистки
(по умолчанию 90 дней). События показа ответа и feedback готовы для агрегации
в будущем A/B-тесте; переход по внешней ссылке и покупка сознательно не
атрибутируются без согласованного домена и контракта платформы.
После «Не помогло» кнопки оценки заменяются одной ненавязчивой кнопкой
«Уточнить вопрос»: она просит пользователя сформулировать уточнение, но не
сохраняет исходный текст. Для локальной разработки сводка без персональных
данных можно получить прямым чтением SQLite только в локальной среде команды.

Негативная оценка попадает в ручную audit queue как один из пяти классов:
проблема поиска, отсутствующий материал, неудачная формулировка,
неподтверждённый факт или ошибка интерфейса. Классификацию делает разработчик
по воспроизводимому тестовому диалогу, а не по сохранённому тексту пользователя.

## Двухслойный ответ и выпускной корпус

Сначала локальная модель выбирает дословные якоря только из хэш-проверенных
фрагментов. Затем она может сформировать короткие `summary`, до трёх `actions`
и `reason`; каждый тезис содержит `evidence_refs`. Приложение проверяет ссылки
на переданный контекст и буквальное наличие чисел. Некорректная структура или
неподтверждённое число дают прежний безопасный fallback с исходным фрагментом.
В Telegram исходная цитата доступна в сворачиваемых источниках; у подкаста там
всегда выпуск и таймкод, а основной текст не должен начинаться репликой спикера.

`assets/corpus_manifest.json` фиксирует тип, разрешённый доступ, source block IDs
и SHA-256 145 release-записей. Runtime сверяет контрольные суммы корпуса при
запуске. Новые материалы допускаются только после ручной проверки происхождения
и доступа. События будущего A/B-теста не должны включать текст
вопроса, username или открытый chat ID; пока нет согласованного домена и
контракта, `/go/`-редирект и атрибуция покупки намеренно не реализованы.

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Токен тестового Telegram-бота; обязателен в Compose. |
| `AI_MODEL`, `AI_MODEL_DIGEST` | Имя и полный SHA-256 локальной модели. |
| `AI_REQUEST_TIMEOUT`, `AI_HTTP_TIMEOUT` | Предел времени запроса и HTTP-вызова модели. |
| `AI_MAX_WORKERS`, `AI_MAX_PENDING` | Ограничения параллелизма и очереди. |
| `AI_PODCAST_CORPUS_PATH`, `AI_PODCAST_CORPUS_SHA256` | Проверенный подкастный корпус и его SHA-256. |
| `GROUP_DELAY_SECONDS` | Короткое окно группировки входящих сообщений. |
| `REMINDERS_PATH` | SQLite-файл заданий и незавершённых подтверждений. |

Compose сам задаёт `AI_ENABLED=true`, путь к упакованному корпусу, адрес
контейнерной Ollama, порт и путь SQLite. Настройки `.env.example` для
локального запуска без Docker также содержат старый режим `OLLAMA_ENABLED`.
Он обращается к Ollama Cloud или произвольной локальной модели без базы знаний
Альфа-Курса. Для основной проверки используйте режим `AI_ENABLED=true`.

## Известные ограничения

- Напоминания проверены в тестах с управляемым временем и подменённой
  Telegram-сессией. 15 ноября 2026 года отдельный тестовый бот доставил одно
  разовое напоминание в разрешённый тестовый чат. 16 ноября в тот же чат
  доставлены три сообщения одного повторяющегося задания: две ежедневные
  доставки, изменение на еженедельное, третья доставка и отмена без последующей
  отправки. Также через входящий polling-диалог создано напоминание «через
  2 минуты»: бот рассчитал время, запросил подтверждение, сохранил и доставил
  сообщение в назначенную минуту. После трёх неудачных отправок задание получает
  статус ошибки и требует ручной проверки.
  Telegram не предоставляет идемпотентный ключ для `sendMessage`, поэтому при
  обрыве процесса между отправкой и фиксацией успеха возможен повтор.
- В Docker включён только один вручную проверенный выпуск подкаста. По другим
  выпускам бот не должен выдавать непроверенные расшифровки.
- Для polling контейнеру нужен прямой доступ к `api.telegram.org`; при сетевой
  блокировке startup завершается ошибкой. После восстановления VPN 16 ноября
  polling поднялся, а `/ready` вернул 200.
- Строгая полнота подтверждений на независимом holdout — 78,3%; два вопроса с
  ответом в корпусе получили отказ или уточнение. Эти случаи не скрываются
  итогом настроенного регрессионного набора.
- Метаданные 18 карточек и доступность ссылок проверены.
- Полное скачивание модели на чистом Docker-хосте ещё не проверено. При
  прерывании загрузки скрипт возобновляет её и сверяет SHA-256.
- `/ready` проверяет метаданные локальной модели и корпус, но не делает пробную
  генерацию; отдельный запрос может завершиться по таймауту даже при 200.
- Переход по рекомендации пока нельзя связать с покупкой без согласованного
  идентификатора или аналитики платформы.
