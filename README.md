# AlfaLearn — АльфаНавигатор

Telegram-бот для кейса «Альфа-Курс»: тестовый помощник для предпринимателей.
Подключена Ollama для текстовых ответов и определения законченного вопроса.
Бот сохраняет историю диалога и отвечает на явный вопрос, понятную просьбу
или релевантный ответ на своё уточнение. Вводные фразы запоминает и молча ждёт
продолжения: сама пауза больше не запускает ответ. Без Ollama доступны прежние заглушки.
Для 18 типов сообщений сохранены тестовые HTTP-маршруты.

Название проекта: **АльфаНавигатор**. Фактический Telegram username определяется
токеном `BOT_TOKEN` и отображается в `/health`.
Материалы курса и поиск по ним (RAG), профиль и напоминания ещё не подключены.

## Запуск на Windows

Для проекта используется Python 3.11 и доступ к Telegram API. Версия закреплена
в `.python-version`. Команды ниже создают окружение на Python 3.11. Из корня проекта:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Укажи токен BotFather в `BOT_TOKEN` в `.env`. В текущем рабочем проекте `.env`
уже заполнен — не перезаписывай его примером.

```powershell
.\.venv\Scripts\python.exe -m alfalearn
```

Один процесс запускает FastAPI и Telegram long polling. Публичный домен,
HTTPS-туннель и webhook для локального запуска не нужны. Запускай только один
экземпляр бота и один worker. Остановка: `Ctrl+C`.

## Подключение Ollama

По умолчанию `OLLAMA_ENABLED=false`: ключ не требуется, текстовые ответы остаются
заглушками. Чтобы включить Ollama Cloud, укажи в локальном `.env`:

```dotenv
OLLAMA_ENABLED=true
OLLAMA_BASE_URL=https://ollama.com
OLLAMA_MODEL=gemma4:31b
GROUP_DELAY_SECONDS=1
```

Добавь свой ключ в `OLLAMA_API_KEY` в том же `.env` и перезапусти приложение.
Ключ хранится на сервере и не должен попадать в Git.
Для облачного режима установка приложения Ollama и загрузка модели на компьютер
не нужны: Python-клиент обращается к `POST https://ollama.com/api/chat`
с `Authorization: Bearer`, `stream=false` и `think=false`.

Для локального режима установи [Ollama для Windows](https://docs.ollama.com/windows)
и запусти её. Затем скачай модель из терминала:

```powershell
ollama pull qwen3.5:4b
```

Настрой локальный `.env`:

```dotenv
OLLAMA_ENABLED=true
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen3.5:4b
OLLAMA_API_KEY=
```

В `OLLAMA_BASE_URL` нужен адрес сервера без `/api`: клиент добавляет `/api/chat`.
HTTP разрешён только для localhost; для удалённого сервера требуется HTTPS.
Если раньше использовался облачный ключ, очисти `OLLAMA_API_KEY` для локального
сервера. При `BOT_ENABLED=false` Ollama продолжает работать через HTTP API.

### Повторный запуск настроенной локальной версии

В текущей Windows-конфигурации используется portable Ollama из
`.run/ollama/ollama.exe`, модель `qwen3.5:4b` и хранилище `.run/ollama-models/`.
После первоначальной установки и загрузки модели запускай из корня проекта:

```powershell
.\scripts\start_local.ps1
```

Скрипт читает `.env`: нужны `OLLAMA_ENABLED=true`, локальный адрес
`http://127.0.0.1:11434`, выбранная модель и пустой `OLLAMA_API_KEY`.
Он ничего не устанавливает и не скачивает. Запускает Ollama и бота в фоне,
проверяет `/api/tags` и `/health` с ожиданием до 30 секунд на каждый сервис.
Уже работающая Ollama на порту 11434 используется повторно.

Перед запуском бота выполняется отдельный прогрев модели через `/api/generate`
без пользовательского запроса, с лимитом 120 секунд и `keep_alive=-1`. Это загружает
модель в память заранее и сокращает ожидание первого вопроса. Модель остаётся
в памяти до остановки сервера. При необходимости лимит первого прогрева можно
изменить: `.\scripts\start_local.ps1 -WarmupTimeoutSeconds 180`.
Для создаваемой Ollama задаются только переменные
дочернего процесса: `OLLAMA_NO_CLOUD=1`, контекст 16384 токена и один параллельный
запрос. Глобальные настройки Windows не меняются. У уже работающего сервера его
настройки сохраняются.

Остановка фоновых процессов этого проекта:

```powershell
.\scripts\stop_local.ps1
```

PID и логи находятся в `.run/bot.pid`, `.run/ollama.pid`, `bot.stdout.log`,
`bot.stderr.log`, `ollama.stdout.log` и `ollama.stderr.log` внутри `.run/`.
PID Ollama записывается только при её запуске скриптом. Остановка проверяет путь,
команду и время создания каждого процесса, включая дочерний Python; при невозможности
проверить принадлежность процесс остаётся работать. Другие экземпляры Python и
посторонняя Ollama, использованная повторно без записи PID, не останавливаются.

Модель отвечает на основе общих знаний, текущего текста и ограниченного контекста
сохранённого разговора. Материалы Альфа-Курса, интернет-поиск и инструменты внешних
действий ей недоступны. Вложения не отправляются модели; ссылки не открываются.
Ответы тестовой модели могут быть неточными.

Документация: [Ollama Cloud](https://docs.ollama.com/cloud),
[Chat API](https://docs.ollama.com/api/chat).

### Если облачная модель не отвечает

HTTP 402 от Ollama Cloud с сообщением `Add usage credits or subscribe` означает,
что для облачных вызовов нужны средства или подходящая подписка. Это само по себе
не означает, что ключ неверный. Пополни баланс, подключи подписку, используй другой
ключ с доступным облачным лимитом или переключись на локальную Ollama по инструкции
выше. После смены настроек перезапусти приложение.

В этом случае приложение остаётся запущенным. При ошибке генерации на распознанный
вопрос Telegram сообщает о временной недоступности Ollama; ошибка классификации
оставляет бота в молчаливом ожидании. `POST /answers` возвращает HTTP 503. `/health` может при этом
оставаться `ok`, поскольку проверяет процесс polling и показывает конфигурацию LLM,
а не баланс аккаунта или доступность генерации. Ключи и текст запросов в логи не выводятся.

## Когда бот отвечает

В режиме Ollama готовность текста определяется по текущему сообщению и истории:

- `QUESTION` — собственный явный вопрос или понятная просьба. Простой самостоятельный
  вопрос, например «Как открыть ИП?», распознаётся быстрым правилом без отдельной
  классификации. Контекстуальное «А сколько будет после налога?» оценивается с учётом
  предыдущего разговора.
- `ANSWER` — релевантный ответ именно на вопрос, который бот действительно задал
  в своём последнем сообщении. Например, после «Каковы расходы?» число «60000»
  продолжает расчёт. Само по себе «да» без актуального вопроса бота не запускает ответ.
- `WAIT` — нет понятного вопроса/просьбы и нет ответа на актуальное уточнение.
  «У меня вопрос», «а если?», незаконченная мысль или цитата чужого вопроса
  сохраняются в истории, а бот молчит. Через секунду, минуту или после перезапуска
  автоматического ответа только из-за прошедшего времени не будет.

Для текста вне быстрого правила классификация ограничена
`CLASSIFICATION_TIMEOUT_SECONDS=2` секундами. Этот лимит независим от секундного
окна группировки. Таймаут, ошибка или неверный формат решения трактуются как
`WAIT`, без ответа и без автоматического уточнения.

`GROUP_DELAY_SECONDS=1` сохраняется для команд и вложений, а также для завершения
временной группы `WAIT` в памяти процесса. Завершение этой группы не удаляет
сохранённый текст и не даёт разрешения ответить. Следующий вопрос получит этот
контекст из истории, даже если между сообщениями была долгая пауза.

Новое сообщение отменяет ещё не отправленный анализ или генерацию. Фрагменты
соединяются переносами строк, решение принимается заново для всей группы.
Уже начавшаяся отправка в Telegram не отменяется; следующее сообщение создаёт
новую группу и учитывает успешно доставленный ответ бота.

«Сразу» означает отсутствие искусственной паузы: подготовка контекста, сеть
и генерация модели всё равно занимают время. Одиночная команда получает свой
служебный ответ, вложения и смешанная группа текст + вложение — заглушку.
Без Ollama сохраняется прежний режим текстовых заглушек.

Если Ollama недоступна при генерации уже распознанного вопроса, бот отвечает коротким
сообщением о временной ошибке и продолжает работать. После изменения `.env`
перезапусти приложение.

## Память диалога и сброс

Текстовая история Telegram в режиме Ollama хранится в SQLite:
`HISTORY_PATH=.run/conversations.sqlite3`. Относительный путь отсчитывается от
корня проекта. В базе остаются полные оригиналы текстовых сообщений пользователя
и успешно доставленных ответов модели. Вводные фразы `WAIT` тоже сохраняются.
Команды, медиафайлы и служебные заглушки не становятся диалогом модели.
Неотправленный или отменённый ответ в историю assistant не добавляется; если длинный
ответ доставлен частично, сохраняются только успешно отправленные части.

История и сводка переживают перезапуск приложения. Память начинается с сообщений,
полученных после внедрения этой функции: прошлую переписку Telegram бот не
восстанавливает. Разные пользователи, чаты, темы и отправители `sender_chat`
имеют отдельные диалоги и не получают чужой контекст.

Модель не получает всю базу целиком. `HISTORY_CONTEXT_CHARS=12000` задаёт бюджет
контекста истории; при его заполнении старые участки сворачиваются в обновляемую
LLM-сводку длиной до 2000 символов, рядом остаются недавние реплики. Текущий запрос
и системные инструкции также учитываются в общем лимите входа модели. Полные
оригиналы при сворачивании не удаляются из SQLite. Сводка может упускать детали
или ошибаться: сохранение оригиналов не означает бесконечную точность памяти
модели и не гарантирует, что любой старый факт попадёт в текущий ответ.

Команда `/reset` очищает историю, сводку и ожидающие задачи только текущего диалога
— сочетания чата, пользователя, темы и `sender_chat`. Другие диалоги сохраняются.
`/start` показывает приветствие и **не сбрасывает память**. Сброс не удаляет уже
отправленные сообщения из самого Telegram.

## Что проверить

- `GET http://127.0.0.1:8000/hello` → `{"message":"Hello, world!"}`.
- `GET http://127.0.0.1:8000/` → тот же ответ.
- `GET http://127.0.0.1:8000/health` → состояние polling, username и конфигурация LLM,
  если она включена. Поле `llm` не является проверкой доступности Ollama.
- `POST http://127.0.0.1:8000/answers` → ответ Ollama при включённом режиме,
  заглушка — при выключенном.
- [Swagger UI](http://127.0.0.1:8000/docs) — документация HTTP API.
- В Telegram: одиночный `/start` — приветствие без сброса истории; `/hello` и `/help`
  — `Hello, world!`; `/reset` — сброс только текущего диалога.
- В Telegram с Ollama: «Как открыть ИП?» сразу запускает ответ; «у меня вопрос»
  остаётся без ответа и после паузы. «Моя кофейня называется Север» сохраняется
  молча; последующий вопрос может использовать это название.
- После реального уточнения бота «Каковы расходы?» число «60000» запускает ответ
  с предыдущим контекстом; без вопроса бота одиночное «да» остаётся `WAIT`.
- Перезапусти приложение и задай вопрос о ранее сообщённых данных: история
  сохраняется. После `/reset` данные этого диалога больше не передаются модели.
- Без Ollama обычный текст, а также неизвестная команда в любом режиме →
  `Извините я пока-что не могу читать ваши сообщения`.
- Голосовое, фото, видео и другие типы → соответствующая заглушка (см. ниже).
- Несколько фрагментов текста → ответ, когда появится вопрос/просьба или релевантный
  ответ на уточнение; альбом → одна заглушка
  после паузы в 1 секунду от последнего сообщения.

```powershell
Invoke-RestMethod http://127.0.0.1:8000/hello
Invoke-RestMethod http://127.0.0.1:8000/health
```

## Ответы

`POST /answers` принимает JSON с непустым строковым полем `message`
длиной до 16 000 символов:

```json
{"message": "Как начать обучение?"}
```

При `OLLAMA_ENABLED=true` HTTP 200 содержит `{"answer": "..."}` с ответом модели.
HTTP-запрос не использует задержку группировки и ничего не отправляет в Telegram.
Этот маршрут остаётся stateless: у него нет `session_id`, он не читает и не дополняет
Telegram-историю и отвечает только по переданному `message`. Правило молчаливого
`WAIT` относится к Telegram-диалогу, а не к этому тестовому HTTP-вызову.
При таймауте или ошибке Ollama API возвращает HTTP 503 с полем `answer`, содержащим
сообщение о временной недоступности.

При `OLLAMA_ENABLED=false` ответ HTTP 200 остаётся прежним:

```json
{"answer": "Извините я пока-что не могу читать ваши сообщения"}
```

Если `message` отсутствует, пустое, состоит из пробелов, превышает лимит
или имеет другой тип, API возвращает HTTP 422.
В Swagger этот эндпоинт находится в разделе «Ответы». Пример для PowerShell:

```powershell
$body = @{ message = "Как начать обучение?" } | ConvertTo-Json
Invoke-RestMethod http://127.0.0.1:8000/answers -Method Post `
  -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
```

### Отдельные типы

Все маршруты ниже используют `POST`, не требуют тела запроса и возвращают JSON
`{"answer": "..."}` с соответствующей заглушкой. Это проверка текста ответа по
известному типу, а не обращение к модели: загружать файлы через HTTP пока не требуется.
Маршруты сохраняют заглушки и при включённой Ollama; для настоящего текстового
ответа используй `POST /answers`.

| Тип сообщения | Маршрут | Содержание тестовой заглушки |
|---|---|---|
| Текст | `/answers/text` | Читать сообщения |
| Голосовое | `/answers/voice` | Прослушивать голосовые сообщения |
| Фото или скриншот | `/answers/photo` | Просматривать фотографии и скриншоты |
| Документ или файл | `/answers/document` | Читать документы и файлы |
| Ссылка | `/answers/link` | Открывать и читать ссылки |
| Видео | `/answers/video` | Просматривать видео |
| Видеокружок | `/answers/video-note` | Просматривать видеокружки |
| Аудиофайл | `/answers/audio` | Прослушивать аудиофайлы |
| Стикер | `/answers/sticker` | Распознавать стикеры |
| GIF | `/answers/gif` | Просматривать GIF-анимации |
| Эмодзи | `/answers/emoji` | Интерпретировать эмодзи |
| Контакт | `/answers/contact` | Обрабатывать контакты |
| Геолокация | `/answers/location` | Обрабатывать геолокацию |
| Пересланный текст или вложение | `/answers/forwarded` | Читать пересланные сообщения и вложения |
| Ответ на сообщение этого бота | `/answers/reply` | Обрабатывать ответы на свои сообщения |
| Сообщение с цитатой | `/answers/quote` | Читать сообщения с цитатами |
| Альбом фотографий или видео | `/answers/album` | Просматривать альбомы фотографий и видео |
| Вложение с подписью | `/answers/caption` | Обрабатывать вложения с текстовыми подписями |

Например, `POST /answers/voice` вернёт:

```json
{"answer": "Извините, я пока не могу прослушивать голосовые сообщения."}
```

### Группы сообщений

`POST /answers/group` — тестовая заглушка, принимающая список типов без обращения
к Ollama. Можно повторять тип для нескольких сообщений одного вида. Все 18 значений
соответствуют последней части маршрутов выше.

```json
{"types": ["photo", "voice", "photo"]}
```

Ответ HTTP 200 — один текст, типы не повторяются:

```json
{"answer": "Извините, я пока не могу обработать эту группу сообщений: голосовое сообщение, фото или скриншот."}
```

Список должен содержать от 1 до 100 известных типов, иначе API возвращает HTTP 422.
HTTP-маршруты не используют окно группировки и не отправляют сообщения в Telegram.

В Telegram типы определяются автоматически по полям сообщения, а не содержимому
файлов. У одного сообщения может быть несколько типов: например, пересланное фото
с подписью. Ссылки определяются по Telegram entities `url`/`text_link`, эмодзи —
по тексту без обычных слов. Цитаты поддерживаются как поле `quote` и как форматирование
`blockquote`/`expandable_blockquote`. GIF с дополнительным полем `document` остаётся GIF.

Бот объединяет сообщения одного отправителя в одном чате и теме. Другие пользователи,
чаты и темы не смешиваются. Для законченного текстового вопроса генерация начинается
сразу; продолжения, команды и вложения обрабатываются по правилам динамической
задержки выше. Одна группа содержит максимум 100 сообщений и 16 000 символов текста,
включая разделители; превышение даёт просьбу сократить вопрос. Ответ модели ограничен
700 генерируемыми токенами и при необходимости делится на сообщения по лимиту Telegram.

Тексты ответов и определение типов находятся в `alfalearn/answers.py`; буфер —
в `alfalearn/grouping.py`, клиент модели — в `alfalearn/llm.py`, хранилище истории —
в `alfalearn/memory.py`, подготовка контекста и сводок — в `alfalearn/conversation.py`.
Файлы не скачиваются, ссылки не открываются. При включённой Ollama текущий текст,
недавняя история и сводка передаются выбранному серверу модели. Временный буфер
хранится в памяти: при остановке процесса анализ, генерация и ожидающие ответы
отменяются, а записанная SQLite-история остаётся.

## Настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `BOT_TOKEN` | — | Секретный токен из BotFather |
| `BOT_ENABLED` | `true` | `false` запускает только HTTP API без Telegram |
| `HOST` | `127.0.0.1` | Адрес HTTP-сервера |
| `PORT` | `8000` | Порт HTTP-сервера |
| `GROUP_DELAY_SECONDS` | `1` | Окно команд/вложений и завершения временной группы WAIT; само по себе не запускает текстовый ответ; от 0.1 до 30 секунд |
| `OLLAMA_ENABLED` | `false` | Включить текстовые ответы и семантическую классификацию Ollama |
| `OLLAMA_BASE_URL` | `https://ollama.com` | Адрес сервера без `/api`; для локальной Ollama — `http://127.0.0.1:11434` |
| `OLLAMA_API_KEY` | пусто | Секретный ключ Ollama Cloud; для локального сервера можно оставить пустым |
| `OLLAMA_MODEL` | `gemma4:31b` | Имя модели на выбранном сервере |
| `OLLAMA_TIMEOUT_SECONDS` | `30` | Общий deadline одного обращения к модели, включая очередь; от 1 до 120 секунд |
| `CLASSIFICATION_TIMEOUT_SECONDS` | `2` | Лимит классификации QUESTION/ANSWER/WAIT, независимый от окна группировки; от 0.05 до 5 секунд |
| `OLLAMA_MAX_CONCURRENCY` | `4` | Максимум одновременных обращений к модели, от 1 до 16 |
| `HISTORY_PATH` | `.run/conversations.sqlite3` | SQLite-файл текстовой истории и сводок; относительный путь от корня проекта |
| `HISTORY_CONTEXT_CHARS` | `12000` | Бюджет истории, передаваемой модели со сводкой; от 4000 до 16000 символов |

Переменные окружения имеют приоритет над `.env`. Сервер проверяет токен и
отсутствие webhook перед запуском. Если webhook уже настроен, запуск завершится
с ошибкой: конфигурацию Telegram нужно сначала переключить на polling.
Если задача polling остановится после запуска, `/health` вернёт HTTP 503.
Включённый облачный режим требует `OLLAMA_API_KEY`. Само наличие конфигурации LLM
в `/health` не подтверждает доступность сервера, действительность ключа или модели:
это проверяется настоящим запросом к `POST /answers` или сообщением боту.

`.env`, виртуальное окружение, настройки IDE, логи и локальные данные в `.run/`,
включая SQLite-историю, исключены из Git. В репозитории хранится `.env.example`
без ключей и переписки.

Локальные `.env` и `.venv/` содержат токен/настройки и установленное окружение.
В `.run/` хранятся portable Ollama, модели, логи, PID и постоянная SQLite-история.
Настройки редактора `.vscode/` и кэши `.pytest_cache/`, `__pycache__/` также
исключены из Git. Остановка приложения не удаляет базу истории.

### Как связаны компоненты

1. `python -m alfalearn` вызывает `__main__.main()`, читает `Settings` и запускает Uvicorn.
2. `api.create_app()` создаёт FastAPI с маршрутами `/`, `/hello`, `/health`, `/answers`
   и `/answers/...` для отдельных типов и группы.
3. При старте FastAPI его `lifespan` открывает SQLite-историю и создаёт клиент Ollama, если режим включён,
   проверяет Telegram-токен и отсутствие webhook, затем запускает
   `Dispatcher.start_polling()` в фоновой задаче того же процесса.
4. `bot.create_dispatcher()` регистрирует обработчики: сначала команды, затем остальные
   сообщения. `AnswerBuffer` записывает входящий текст, подготавливает историю
   через `DialogueContext` и определяет QUESTION/ANSWER/WAIT. Генерация запускается
   только для готового текстового запроса; служебные команды и медиа получают свои
   ответы. После успешной доставки `message.answer()` ответ модели записывается
   в историю исходного диалога.
5. `/health` проверяет состояние задачи polling; при остановке приложения задача
   отменяется, сессии Telegram и Ollama и соединение SQLite закрываются. При `BOT_ENABLED=false`
   работает только HTTP API, включая Ollama, если она включена.

SQLite используется для диалоговой истории; поиска по материалам курса пока нет.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты проверяют HTTP-ответы и валидацию, все 18 типов, команды, альбомы,
смешанные группы, строгую готовность вопроса и молчаливый WAIT, сохранение истории
после перезапуска, сброс и изоляцию диалогов, ограничение контекста и сводки,
отмену устаревшего анализа и генерации, ошибки Ollama и остановку задач.
Запросы к Telegram и Ollama заменены моками.
Для повторной настройки имени, публичного описания и
команд бота (токен берётся из `.env`):

```powershell
.\.venv\Scripts\python.exe -m scripts.configure_bot
```

Основные зависимости зафиксированы в `requirements.txt`; полный снимок
проверенного окружения, включая тестовые зависимости, — `requirements.lock`.
Для его воспроизведения: `python -m pip install -r requirements.lock`.

Документация: [aiogram polling](https://docs.aiogram.dev/en/latest/dispatcher/long_polling.html),
[FastAPI lifespan](https://fastapi.tiangolo.com/advanced/events/).
