# Локальная приёмка AI/ML AlfaLearn

Модуль запускается и проверяется отдельно от приложения. Для ответов по базе нужна локальная Ollama. Подбор карточек и разбор явных команд напоминания выполняются кодом.

```powershell
uv sync --locked
uv run --locked python -m unittest discover -s tests -q
uv run --locked --group corpus python -m unittest discover -s tests/corpus -q
uv run --locked python -m scripts.eval_recommendations --output data/local/recommendations.eval.jsonl
uv run --locked python -m scripts.eval_recommendations --split transfer --output data/local/recommendations.transfer.jsonl
uv run --locked python -m scripts.eval_rag --split dev
uv run --locked python -m scripts.eval_rag --split regression
uv run --locked python -m scripts.eval_rag --split control
uv run --locked python -m scripts.eval_rag --split business
uv run --locked python -m scripts.eval_rag --split acceptance
uv run --locked python -m scripts.eval_rag --split expanded
uv run --locked python -m scripts.eval_rag --split transfer
uv run --locked python -m scripts.eval_ai_acceptance
```

## Сценарии

**Ответ с источником и следующий шаг.** База включает 30 проверенных фрагментов 13 статей и 18 карточек. Подкасты подключаются из [локального каталога](PODCASTS.md). Поле `recommendations` содержит до двух подходящих карточек. Карточка, уже использованная как источник, исключается из списка.

```powershell
uv run --locked alfa-ai --query "Как выбрать принтер этикеток для Ozon?"
```

**Подбор без генерации.** У каждой карточки есть ID из выгрузки, формат, тип доступа, исходная ссылка и публичное описание пользы. Ограничение «только бесплатное» исключает покупку и подписку. Модель ответа получает только допущенные фрагменты корпуса. Описания подписочных и платных карточек используются отдельно при ранжировании. Сравнить режимы можно на официальном [подписочном подкасте](https://kurs.alfabank.ru/podcasts/kassovyj-razryv-ne-prigovor-kak-upravlyat-finansami-biznesa/) и [бесплатном курсе](https://kurs.alfabank.ru/courses/marketpleysy-s-chego-nachat-kak-preuspet/).

```powershell
uv run --locked alfa-ai --query "Где найти курс по УСН на маркетплейсах?"
uv run --locked alfa-ai --recommend-only --query "Что послушать про кассовый разрыв?"
uv run --locked alfa-ai --recommend-only --free-only --query "Что послушать про кассовый разрыв?"
```

**Контекст и профиль.** Сервис принимает предыдущее содержательное сообщение в `previous_query` и возвращает явно сказанные изменения в `profile_patch`. Для короткого уточнения он подставляет подтверждённую сферу бизнеса. Поддерживаются салон, кофейня и магазин. Профиль передаётся отдельно для каждого запроса.

```powershell
uv run --locked alfa-ai --previous-query "Как вернуть клиентов, которые давно не приходили?" --query "А для моего салона?"
uv run --locked alfa-ai --query "А для моего салона?"
```

**Напоминания.** Явная команда выдаёт `action_proposal` с параметрами для подтверждения. Неполная команда выдаёт `clarify` и `missing_fields`. Поддерживаются разовая дата, ежедневный повтор, повтор по конкретному дню недели, изменение и отмена по номеру. Можно ответить коротким слотом времени, даты или пояса и передать предыдущую команду. Проверяются прошедшее время, невозможная дата и неоднозначный час перехода на летнее время. Для напоминаний о налогах дату задаёт пользователь.

```powershell
uv run --locked alfa-ai --now 2026-11-12T16:00:00+03:00 --timezone Europe/Moscow --query "Напомни завтра в 18:00 пройти курс"
uv run --locked alfa-ai --now 2026-11-12T16:00:00+03:00 --timezone Europe/Moscow --query "Напоминай каждый понедельник в 09:00 учиться"
uv run --locked alfa-ai --query "Отмени напоминание #r42"
```

Сохранение, подтверждение владельца и доставка относятся к исполнительному слою. Поле `needs_confirmation` требует подтверждения перед выполнением.

## Проверка расширения корпуса

Набор `acceptance` содержит 10 новых формулировок. На исходных шести статьях прошли 5 из 10. Во всех пяти провалах требуемого материала не было в допущенном корпусе. После добавления пяти фрагментов о доставке по району, PEST-анализе и работе с жалобами прошли 10 из 10. Для семи вопросов с ответом поиск нашёл все нужные фрагменты в первых трёх результатах. Медиана ответа на локальной модели составила 4,49 с, максимум — 8,32 с в этом прогоне. Рекомендации отдельно прошли 20 из 20 проверок.

При ручном чтении ответы сохранили нужные факты и условия. В вопросе об убыточной доставке вместе с ключевой причиной выводятся другие пункты списка. В вопросе о переписке цитата также включает совет для очного общения. Набор использован для расширения корпуса и теперь служит для проверки регрессий.

Четыре прежних набора (`dev`, `business`, `regression`, `control`) дали 30 из 30 успешных автоматических проверок на расширенном корпусе. Прогон поиска по одному выпуску подкаста и всем девяти статьям описан в [результатах подкастов](PODCASTS.md#проверки-и-пределы-пилота).

## Воспроизведение из исходного архива

Для повторной проверки архив восстановлен в новую локальную базу PostgreSQL 17. Экспорт подготовил 25 статей и 415 фрагментов. Модуль допустил 30 фрагментов по контрольным суммам. Следующие команды создают отдельную базу проверки. Запусти существующий контейнер из `compose.restore.yaml` и при выгрузке введи его пароль.

```powershell
$db = 'alfa_ai_acceptance_' + (Get-Date -Format 'yyyyMMddHHmmss')
docker exec alfa-restore-postgres-1 createdb -U alfa $db
docker exec alfa-restore-postgres-1 pg_restore -U alfa -d $db --no-owner --no-privileges --exit-on-error /backup/alfa_course_hackathon.backup
$env:PGDATABASE = $db
uv run --locked --group corpus python -m scripts.prepare_articles --ask-password --output data/local/fresh-restore-articles.jsonl
Remove-Item Env:PGDATABASE
uv run --locked --group corpus python -m scripts.chunk_articles --input data/local/fresh-restore-articles.jsonl --output data/local/fresh-restore-chunks.jsonl
$env:AI_CORPUS_PATH = (Resolve-Path 'data/local/fresh-restore-chunks.jsonl').Path
uv run --locked python -m scripts.eval_ai_acceptance --output data/local/ai-acceptance-fresh-restore.jsonl
```

Успешный прогон требует запущенной локальной Ollama и настроек модели из [инструкции интеграции](INTEGRATION.md). Отчёт API сохраняет вход, результат и несовпадения с ожидаемым поведением для каждого сценария.

## Результаты локальных проверок

| Проверка | Результат |
| --- | --- |
| Автономные тесты Python, RAG и подготовки корпуса | 89/89 |
| Ответы по статьям, все семь наборов | 52/52 |
| Подбор карточек, включая ограничения доступа | 32/32 |
| Python API (`eval_ai_acceptance.py`) | 16/16 |
| Подкасты с разметкой, исправленной расшифровкой и E5, прежние вопросы | 26/26 |
| Подкасты в той же конфигурации, новые вопросы | 9/9 |

В наборе по статьям новые поисковые формулировки помогли найти фрагменты о фиксации решений удалённой команды и LTV. При многоточии в цитате модуль сверяет обе части и возвращает исходный текст между ними. Сквозные проверки подтверждают сохранение частей артикула BLU и XS и причины, по которой термопринтер плохо подходит для долгого хранения. Набор `transfer` теперь проверяет регрессии.

При выборочной ручной сверке ответы о решениях после созвона и значении LTV содержат искомые сведения. Ответ об артикуле приводит также пункты про страну, производителя, категорию и материал. Ответ о жалобе в чате включает совет для очного общения из того же абзаца.

Python API проверен на коротких продолжениях, смене темы, онбординге, ограничениях рекомендаций и предложениях создать, изменить и отменить напоминание. Контракт и параметры окружения приведены в [инструкции интеграции](INTEGRATION.md).

Wheel устанавливается в отдельное окружение Python 3.12. Для проверки запуска используй вопрос про термопринтер и прямой запрос курса по УСН. Первый проверяет ответ по корпусу и локальную модель, второй — поиск по каталогу.

После рефакторинга для 0.1.2 повторены 89 тестов, 32 проверки рекомендаций, 16 сценариев Python API и 35 вопросов по подкастам. Локальные отчёты сквозных прогонов — `data/local/ai-acceptance-0.1.2.jsonl` и `data/local/podcast-acceptance-0.1.2.jsonl`. Скрипт оценки статей печатает пути к отчётам со статусами, источниками и выдержками для ручной проверки.

## Что осталось

1. Проверить расшифровки подкастов вручную на имена, числа и термины. Текущие метрики и результаты повторного распознавания приведены в [отчёте по подкастам](PODCASTS.md#проверка-с-разметкой-и-дополнительным-семантическим-поиском).
2. Расширять корпус по темам демонстрации после проверки публичности и доступа. Текущая база ответов охватывает 13 статей. Для других тем ожидаем корректный отказ или уточнение.
3. При интеграции проверить контракт на реальном обработчике приложения, сохранение профиля и доставку напоминаний после подтверждения. Это отдельная проверка после локальной приёмки.
