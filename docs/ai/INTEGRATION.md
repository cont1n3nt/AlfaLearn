# Подключение AI-модуля AlfaLearn

Версия контракта: 1, пакет `alfalearn-ai==0.1.2`, импорт `alfa_ai`, Python 3.12.
Локальная проверка модуля описана в [сценариях приёмки](LOCAL_ACCEPTANCE.md). В этом репозитории Telegram и `POST /answers` используют `AIService` при `AI_ENABLED=true`. [Запуск бота](../../README.md#aiml).

## Установка и входные данные

В этом репозитории: `uv sync --locked`. В проекте бота можно добавить локальную зависимость:

```text
uv add --editable D:/User/code/AlfaLearn
```

Либо собрать wheel командой `uv build --wheel` и установить полученный файл как зависимость проекта бота. Wheel содержит только пакет и метаданные: backup, исходные документы, корпус и отчёты в него не входят. Локальная сборка не означает разрешения публиковать код или данные.

Backend должен указать абсолютный `AI_CORPUS_PATH` до создания сервиса. В режиме разработки путь по умолчанию — `data/local/pilot_chunks.jsonl` относительно текущей рабочей директории. При отсутствии, дублировании или изменении допущенных фрагментов запуск завершается ошибкой. Исходный PostgreSQL во время ответов не нужен.

Ollama запускается отдельно. Ожидаются модель и SHA-256 из `.env.example`; они проверяются до генерации. Настройка имени и digest позволяет явно выбрать другую локальную модель, но её качество придётся оценить заново. В этой версии допустим только локальный HTTP-адрес `127.0.0.1` или `[::1]`; прокси, перенаправления и облачные модели не используются. Docker-интеграция с отдельным хостом Ollama потребует отдельной настройки сетевой границы.

## Жизненный цикл

Создай один сервис при запуске приложения. Передавай этот экземпляр в обработчики через зависимости. Вызывай `aclose()` при остановке. Один экземпляр принадлежит одному event loop.

```python
from alfa_ai import AIRequest, AIService, Settings

async def example():
    settings = Settings.from_env()
    async with await AIService.create(settings) as ai:
        result = await ai.answer(AIRequest(query="Как учитывать бонусы клиентов салона?"))
        return result.to_dict()
```

В приложении бота создание сервиса происходит на startup, а `await ai.answer(...)` — на каждое сообщение. Не создавай новый сервис внутри каждого обработчика. Сервис не отправляет сообщения в Telegram и не владеет токеном бота.

## Контракт

Вход — `AIRequest(query: str)`: от 1 до 1000 символов после удаления пробелов по краям. Ошибка входного типа или длины вызывает `ValueError` до обращения к модели. Неизвестные поля конструктора вызывают `TypeError`.

Опциональные поля запроса: `profile`, `previous_query`, `now` и `timezone`. Сервис возвращает `profile_patch` с явно сказанными сведениями и `proposed_action` для команды напоминания. Вызывающее приложение отвечает за хранение профиля и передачу контекста конкретного пользователя.

Если сервис попросил уточнить выпуск, передай исходный вопрос в `previous_query`, а название или ссылку из короткого ответа пользователя — в `query`. Сервис использует исходный вопрос и ограничивает поиск выбранным выпуском. Примеры есть в [инструкции по подкастам](PODCASTS.md).

Модуль держит профиль только в полученном запросе. Применяй поля `profile_patch` поверх профиля текущего пользователя, сохраняя остальные поля. Для продолжения напоминания передавай исходную незавершённую команду как `previous_query` и дополнение пользователя как `query`. Если нужно несколько дополнений, храни исходную команду вместе с уже собранными параметрами в рамках одного диалога.

```python
from datetime import datetime

from alfa_ai import AIRequest

request = AIRequest(
    query="18:00",
    previous_query="Напомни завтра пройти курс",
    timezone="Europe/Moscow",
    now=datetime.fromisoformat("2026-11-14T12:00:00+03:00"),
)
```

Ожидается `action_proposal` с `action="create_reminder"`, `local_datetime="2026-11-15T18:00"` и `needs_confirmation=True`. Для `clarify` используй `missing_fields` при наличии предложения. Перед сохранением, изменением или отменой получи подтверждение и проверь, что выбранное напоминание принадлежит пользователю.

Выход — `AIResponse`; метод `to_dict()` возвращает JSON-совместимый словарь:

```json
{
  "status": "answer",
  "text": "Ответ со ссылкой [S1]",
  "trace_id": "уникальный UUID запроса",
  "sources": [{
    "source_id": "S1",
    "document_id": "article:...",
    "chunk_id": "...",
    "title": "Название материала",
    "source_block_orders": [13],
    "url": "https://..."
  }],
  "error_code": null,
  "recommendations": [],
  "profile_patch": {},
  "proposed_action": null
}
```

`answer.text` начинается с «В проверенных материалах:» и содержит исходные абзацы со ссылками. Модель выбирает цитаты, а модуль восстанавливает абзацы, объединяет пересечения и сохраняет порядок внутри источника. Показывай абзацы целиком, чтобы сохранить условия и отрицания.

Backend отображает текст и источники; автоматически интерпретировать текст модели как команды или HTML нельзя. Используй обычный текст либо экранируй его средствами выбранного режима отображения. Сохранять источники и чужие ответы в общей истории не требуется.

Текущий бот сохраняет профиль консультации и предыдущий запрос по ключу диалога в SQLite. Команда `/reset` очищает их вместе с историей. Сохранение расписаний и доставка уведомлений пока не подключены.

| Статус | Поведение backend |
| --- | --- |
| `answer` | Показать ответ и проверенные ссылки. |
| `clarify` | Показать уточнение. Для короткого продолжения передать предыдущий запрос этого же пользователя. |
| `action_proposal` | Показать расписание и запросить подтверждение перед выполнением действия. |
| `no_answer` | Показать `text` и карточки из `recommendations`, если они есть. Для запроса только о подборе карточек `text` описывает результат поиска по каталогу. |
| `error` | Показать безопасный текст ошибки; техническое решение принимать по `error_code`. |

Коды ошибок: `busy`, `timeout`, `unavailable`, `model_unavailable`, `invalid_response`, `internal_error`, `closed`. Ошибки сервиса не подменяются отсутствием знаний. Неподтверждённая цитата отбрасывается и приводит к `no_answer`, как и в пилоте. Для анализа цитат используй локальный оценочный прогон, а не пользовательский ответ.

## Параллелизм и остановка

- `AI_MAX_WORKERS=1`: одновременно работает не более одного запроса к локальной модели на экземпляр сервиса.
- `AI_MAX_PENDING=4`: общий предел выполняющихся и ожидающих запросов. При превышении сразу возвращается `busy`, без неограниченной очереди.
- `AI_REQUEST_TIMEOUT=60`: время ожидания ответа, включая очередь.
- `AI_HTTP_TIMEOUT=45`: таймаут сетевой операции локального клиента. Это не жёсткий предел всей генерации на стороне Ollama.
- При отмене coroutine вызывающий код получает `CancelledError`. Задание из очереди отменяется; уже выполняющийся синхронный HTTP-вызов продолжает занимать слот до фактического завершения.
- `aclose()` запрещает новые запросы, отменяет ожидающие задания и ждёт завершения выполняющихся. Остановка может занять время сетевого ожидания. Клиентский таймаут не гарантирует мгновенной остановки вычислений в Ollama.

Ограничения действуют на один экземпляр. Для нескольких процессов нужен общий контроль нагрузки или отдельный обслуживающий процесс. Для одного явно выбранного выпуска модуль может повторить выбор цитат в рамках того же запроса. При `busy` или `timeout` покажи пользователю текст ошибки.

## Проверка перед подключением Telegram

```text
uv run --locked python -m unittest discover -s tests -v
uv run --locked alfa-ai --query "Нужно обсудить ошибку подчинённого: наедине или при коллегах?"
uv run --locked python -m scripts.eval_rag --split control
```

Автономные тесты используют синтетические данные и проверяют отзывчивость event loop, изоляцию результатов, перегрузку, отмену, таймаут, остановку, ошибки, контракт и восстановление исходных абзацев. Набор `--split regression` содержит `h01`–`h08` и `k04`, использованные при настройке. В контрольном наборе остаются пять других вопросов из серии `k01`–`k06`.

Текущие границы корпуса, диалога, рекомендаций и напоминаний зафиксированы в [локальной приёмке AI/ML](LOCAL_ACCEPTANCE.md). После неё контракт проверяется с обработчиками приложения.
