# Подкасты в базе знаний AlfaLearn

Модуль принимает проверенную расшифровку с таймкодами. Он группирует реплики в интервалы около 30 секунд и при необходимости расширяет окно до 45 секунд в поисках конца предложения. Отдельные реплики остаются целыми. Пауза от пяти секунд начинает новый фрагмент. Фрагменты ищутся вместе со статьями, а ответ собирается из текста расшифровки.

## Что есть в выгрузке

Эти признаки помогают отобрать кандидатов для проверки. Четыре строки `PodcastFiles` не разрешаются в `Files`. В `PodcastDetails` 28 коротких описаний длиной до 91 символа. По ним можно понять тему, но нельзя определить, что прозвучало на конкретной минуте.

## Подготовка выпуска

Существующие субтитры можно привести к JSON по образцу [учебного выпуска](../../tests/fixtures/podcast-demo.json). У каждого выпуска есть `episode_id`, `title`, проверенный HTTPS URL и массив `cues`. Реплики должны идти по времени без пересечений и содержать `start_sec`, `end_sec` и `text`.

### Импорт готовых расшифровок

Скрипт принимает ранее сохранённый `results.json` медиа-сервиса. Если в экспорте указан `external_id`, он должен совпадать с идентификатором выпуска.

```powershell
uv run --locked python -m scripts.import_podcast_export --input data/local/results.json --episode-id "<UUID выпуска>" --title "<Название>" --url "<HTTPS-страница выпуска>" --output data/local/podcast.imported.candidate.json
```

Импорт читает `segments` и переносит времена воспроизведения из `t_start` и `t_end`. Опция `--speaker-segments` выбирает дорожку с разделением голосов. При смене метки голоса начинается новый поисковый фрагмент. Метки вроде `Speaker 1` обозначают разные голоса внутри записи. Для пользовательской ссылки указывай страницу из каталога выпуска. Результат проверяется и подключается по SHA-256 так же, как собственная расшифровка.

Проверка совместимости использовала локальный выпуск о сервисе, представленный в формате экспорта. Импорт сохранил 1323 реплики и их таймкоды, повторно построив 82 фрагмента. Запрос через `alfa-ai` вернул ссылку и интервал 576,72–621,72 секунды.

### Распознавание аудио и видео

Для локальной аудиозаписи используй `scripts/transcribe_podcast.py` и папку с моделью Whisper для CTranslate2. Скрипт обрабатывает файл на CPU, выводит кандидат на проверку и его контрольную сумму. Пример команды после подстановки своих путей и данных:

```powershell
uv run --locked --group asr python -m scripts.transcribe_podcast --audio data/local/episode.wav --model-dir data/local/whisper-model --episode-id episode-1 --title "Название выпуска" --url "https://example.org/podcast" --output data/local/podcast.candidate.json
```

Для MP4 или другого локального видео передай `--video` вместо `--audio`. Скрипт использует первую аудиодорожку и учитывает её начальное смещение относительно шкалы воспроизведения. Таймкоды рассчитаны на непрерывную аудиодорожку.

### Разделение спикеров

В интервью можно включить локальное разделение голосов. Понадобятся ONNX-модели сегментации и эмбеддингов. Проверяемая конфигурация использует pyannote segmentation 3.0 и 3D-Speaker ERes2Net. [Сегментация](https://github.com/k2-fsa/sherpa-onnx/releases/tag/speaker-segmentation-models) · [Эмбеддинги спикеров](https://github.com/k2-fsa/sherpa-onnx/releases/tag/speaker-recongition-models).

```powershell
uv run --locked --group diarization python -m scripts.transcribe_podcast --video data/local/episode.mp4 --model-dir data/local/whisper-model --episode-id episode-1 --title "Название выпуска" --url "https://example.org/podcast" --speaker-segmentation data/local/diarization-models/sherpa-onnx-pyannote-segmentation-3-0/model.onnx --speaker-embedding data/local/diarization-models/3dspeaker_speech_eres2net_base_sv_zh-cn_3dspeaker_16k.onnx --speakers 2 --output data/local/podcast.speakers.candidate.json
```

Указывай `--speakers`, только если число спикеров известно. Whisper выдаёт интервалы слов. Скрипт сопоставляет их с интервалами голосов и разделяет реплики при смене спикера. Метки `Speaker 1`, `Speaker 2` различают голоса внутри записи. Сопоставление меток с именами ведущего и гостя требует ручной проверки.

На 90-секундном фрагменте выпуска о сервисе получились 25 реплик, из которых 24 получили одну из двух меток. Реплики прошли проверку порядка и непересечения таймкодов. Для оценки точности меток нужна разметка голосов по аудио. Каталог, подключённый к боту, меняется только после проверки новой расшифровки.

Сверь доступ к записи, ссылку, текст и таймкоды перед подключением. Контрольная сумма фиксирует именно проверенную версию файла. После правок пересчитай её. Храни реальные записи, модели и расшифровки в `data/local/`.

## Подключение и проверка

С запущенной Ollama выполни в PowerShell:

```powershell
$env:AI_PODCAST_CORPUS_PATH = (Resolve-Path 'tests/fixtures/podcast-demo.json').Path
$env:AI_PODCAST_CORPUS_SHA256 = (Get-FileHash -LiteralPath $env:AI_PODCAST_CORPUS_PATH -Algorithm SHA256).Hash.ToLowerInvariant()
uv run --locked alfa-ai --query "Когда в мастерской Лазурный енот проводят инвентаризацию?"
```

Ожидаются `status: answer`, источник `podcast:demo-workshop` и диапазон `12.5–25` секунд. Этот выпуск вымышленный, а URL служит примером. Для реального запуска используй свой проверенный файл вместо примера и вычисли его SHA-256.

В источниках подкаста `start_sec` и `end_sec` задают интервал найденного фрагмента, а `source_block_orders` пуст. Бот может показать «Название выпуска · 00:12–00:25» рядом с исходной ссылкой. Ссылку на конкретную секунду следует формировать только при поддержке плеером. У источников статей формат прежний. При отсутствии обеих переменных подкасты не добавляются в индекс.

### Поисковые термины и проверка цитат

После сверки отрывка можно добавить к реплике поле `search_terms` длиной до 240 символов. Например, к реплике о просьбе высказать мнение можно добавить термин «сбор отзывов». Термины участвуют в лексическом поиске. Модель получает исходный текст реплики, а таймкод и ID фрагмента сохраняются.

Для пакетной разметки `scripts/annotate_podcasts.py` принимает JSON вида `{"episode-id": {"123.5": "поисковые термины"}}`. Время в секундах должно попадать внутрь размечаемой реплики. Укажи новый выходной файл и используй его SHA-256 при подключении.

Если повторное распознавание подтвердило ошибку пунктуации или текста, передай `--corrections`. Файл хранит список правок по выпуску. Каждая запись содержит `start_sec`, исходный `before` и исправленный `after`. Скрипт проверяет исходный текст и сохраняет время реплики.

```powershell
uv run --locked python -m scripts.annotate_podcasts --input data/local/podcast-three-real.candidate.json --terms data/local/podcast-three-real.terms.json --corrections data/local/podcast-servis.punctuation.json --output data/local/podcast-three-real.checked.json
```

Если выбор цитат по одному явно указанному выпуску не прошёл проверку или был обрезан, модуль делает одну повторную попытку. Если в первой попытке были дополнительные результаты E5, остаются четыре лексических фрагмента. Иначе модель получает просьбу выбрать до двух коротких цитат. Обе попытки проходят проверку по расшифровке. Если цитата начинается с отсылки вроде «Этот фильм», модуль добавляет предыдущий абзац того же фрагмента.

## Проверки и пределы пилота

На синтетическом выпуске проверены ответ с интервалом, отказ при отсутствии факта и ответ по статье в том же индексе. Распознавание тестового WAV выполнено локально через `faster-whisper` 1.2.1 и PyAV 16.1.0. Первая попытка с автоматически выбранным PyAV завершилась ошибкой вызова декодера, поэтому совместимая версия закреплена в скрипте.

Выпуск о сервисе распознан Whisper small. Полный результат сохранён в `data/local/podcast-servis.candidate.json`. Он содержит 1323 реплики, из которых после группировки по предложениям получено 82 поисковых фрагмента. Четыре интервала для оценки выделены по отдельным коротким прогонам распознавания. При сверке обнаружены ошибки в написании имени гостьи и отдельных слов. Это выборочная проверка, поэтому файл остаётся кандидатом для включения.

| Метод | Hit@1 | Hit@3 |
| --- | ---: | ---: |
| TF-IDF | 1/4 | 3/4 |
| multilingual E5 | 4/4 | 4/4 |
| RRF | 2/4 | 4/4 |

Отчёт итогового сравнения — `data/local/podcast-servis.retrieval-sentences.jsonl`. В сквозном прогоне вопрос о том, как дать клиенту салона отдохнуть от шума, вернул ссылку на выпуск и интервал 576,72–621,72 секунды. Запрос отсутствующего номера кассового аппарата вернул `no_answer`. Для вопроса о признаке благодарности нужный отрывок был среди результатов TF-IDF, но модель не приложила цитату, поэтому приложение отклонило черновик. Длинные фразы всё ещё могут обрываться на границе окна.

По умолчанию рабочий модуль использует TF-IDF. На четырёх вопросах одного выпуска E5 дал более точное ранжирование. Для постоянного подключения выпуска нужна сверка распознанных имён, чисел и цитируемых отрывков.

Повтор на тех же четырёх вопросах после расширения базы до 17 фрагментов статей. У TF-IDF Hit@1 остался 1/4 и Hit@3 — 3/4. У E5 эти показатели составили 3/4 и 4/4, у RRF — 0/4 и 4/4. Отчёт — `data/local/podcast-servis.retrieval-expanded-articles.jsonl`.

Для сравнения поиска на подключённой расшифровке используй `scripts/eval_podcasts.py`. В файле вопросов нужны поля `id`, `episode_id`, `question`, `start_sec` и `end_sec`. Попаданием считается фрагмент того же выпуска, который перекрывает хотя бы половину размеченного интервала. Опция `--e5` добавляет E5 и объединение рангов RRF. Отчёт пишет найденные интервалы и позиции без текста расшифровки.

```powershell
uv run --locked --extra semantic python -m scripts.eval_podcasts --cases data/local/podcast-servis.cases.json --output data/local/podcast-servis.retrieval-sentences.jsonl --e5
```

## Проверка смешанного индекса

Проверка включает 17 фрагментов статей, одну реальную расшифровку и два вымышленных выпуска с совпадающими таймкодами и разными ответами. В наборе 13 вопросов с интервалами. Пять новых интервалов реального выпуска сверены повторным локальным распознаванием коротких отрывков той же записью модели Whisper small.

| Метод | Реальный выпуск, Hit@1 | Реальный выпуск, Hit@3 | Учебные выпуски, Hit@3 |
| --- | ---: | ---: | ---: |
| TF-IDF | 2/9 | 5/9 | 4/4 |
| E5 | 4/9 | 5/9 | 4/4 |
| RRF | 1/9 | 5/9 | 4/4 |

Для всех 13 вопросов в индексе есть фрагмент, перекрывающий не меньше половины эталонного интервала. У методов разные пропуски. На вопросе об извинениях нужный фрагмент стоял четвёртым у E5 и 41-м у TF-IDF. На вопросе о работе с клиентами в низкий сезон он был вторым у TF-IDF и шестым у E5. В отчёте `full_rank` показывает позицию до отсечения, а `best_index_coverage` помогает отличить промах ранжирования от пробела в нарезке. Поиск в рабочем модуле пока использует TF-IDF.

Через `AIService.answer()` получены 4 из 9 ответов с нужным источником и интервалом по реальному выпуску. В одном из пяти остальных случаев модель сослалась на статью вместо подкаста, в четырёх воздержалась. В учебных выпусках три ответа из четырёх сослались только на нужную запись. Четвёртый смешал два расписания. В отдельном вопросе без названия мастерской модель выбрала выпуск без уточнения. Проверки ответа по статье и отказа при отсутствии факта прошли. Таймкод указывает границы поискового фрагмента, поэтому может начинаться раньше цитируемой реплики. Написание имени гостьи в автоматической расшифровке всё ещё требует сверки.

Для повторения поиска собери локальный каталог из исходного кандидата и учебных выпусков. Расшифровки, отчёты и повторное распознавание остаются в `data/local/`.

```powershell

import json
from pathlib import Path

base = Path("data/local")
catalog = json.loads((base / "podcast-servis.candidate.json").read_bytes())
fixtures = json.loads(Path("tests/fixtures/podcast-eval-extra.json").read_bytes())
catalog["episodes"].extend(fixtures["episodes"])
(base / "podcast-mixed.candidate.json").write_text(

'@ | uv run --locked python -
$env:AI_PODCAST_CORPUS_PATH = (Resolve-Path 'data/local/podcast-mixed.candidate.json').Path
$env:AI_PODCAST_CORPUS_SHA256 = (Get-FileHash -LiteralPath $env:AI_PODCAST_CORPUS_PATH -Algorithm SHA256).Hash.ToLowerInvariant()
```

## Выбор выпуска в ответах

Когда пользователь называет выпуск полным названием, именем в кавычках из заголовка или даёт ссылку из каталога, в контекст модели попадают только названные выпуски. Сопоставление учитывает регистр, пунктуацию и `е/ё`, но требует совпадения слов. Если в каталоге несколько записей и запрос отсылает к неназванному выпуску («из этого выпуска», «из учебного выпуска»), сервис просит указать название. Если общий запрос приводит к цитатам из разных подкастов, сервис тоже уточняет выпуск. Явно названные выпуски можно сравнить.

При подключённом смешанном каталоге эти команды показывают уточнение и ответ на исходный вопрос после выбора записи.

```powershell
$question = 'В какой день в мастерской из учебного выпуска пересчитывают запасы?'
uv run --locked alfa-ai --query $question
uv run --locked alfa-ai --previous-query $question --query 'Мятный кит'
```

## Сквозная проверка источников

Параметр `--answers` дополнительно запускает модель и проверяет цитаты в ответах. Отчёт показывает, попал ли нужный интервал в контекст, процитировала ли его модель и есть ли ссылки на посторонние материалы. Статус ошибки различает сбой запуска, промах поиска и ошибку выбора цитаты. Смысл и полнота ответа проверяются отдельно.

В повторном прогоне прошли 8 из 13 вопросов с эталонными интервалами. Учебные выпуски дали 4 из 4. Реальный выпуск дал 4 из 9: в четырёх случаях нужный интервал остался за пределами первых трёх результатов, в одном был найден, но модель не приложила цитату. В одном из промахов поиска модель ответила по похожей статье. Отчёт — `data/local/podcast-mixed.end-to-end.jsonl`.

Эксперимент с повторным выбором по номерам абзацев восстановил цитату на вопросе о лояльности, но на другом вопросе модель выбрала соседнюю реплику, которая не содержала ответа. Повторный выбор отключён. Для независимой проверки качества по-прежнему нужна вторая реальная запись.

```powershell
uv run --locked --extra semantic python -m scripts.eval_podcasts --cases tests/fixtures/podcast-eval-cases.json --output data/local/podcast-mixed.end-to-end.jsonl --answers
```

## Семантический поиск внутри выбранного выпуска

Опциональный режим использует локальный multilingual E5, когда запрос называет выпуск или содержит его ссылку. При одном выбранном выпуске к четырём результатам TF-IDF добавляются до двух других фрагментов из E5. При сравнении явно выбранных выпусков E5 ранжирует кандидатов в пределах общего лимита трёх фрагментов. Запросы по общему каталогу используют TF-IDF. Заголовок исключается из семантического запроса и семантического индекса расшифровки.

Для запуска установи дополнительные зависимости и укажи папку с `tokenizer.json` и `onnx/model.onnx` из снимка `intfloat/multilingual-e5-base` ревизии `d13f1b27baf31030b7fd040960d60d909913633f`. Веса загружаются из указанной папки при запуске. После запуска модель не обращается к сети.

```powershell
uv sync --locked --extra semantic
$env:AI_E5_MODEL_DIR = '<путь к локальному снимку E5>'
uv run --locked --extra semantic alfa-ai --query 'Как предлагают собирать отзывы? Выпуск «Сервис в малом бизнесе: как удержать клиентов и заработать больше».'
uv run --locked --extra semantic python -m scripts.eval_podcasts --cases tests/fixtures/podcast-eval-cases.json --output data/local/podcast-mixed.named-e5.jsonl --answers --name-episodes
```

В эксперименте на тех же девяти вопросах поиск E5 по тексту фрагмента повысил попадание в первую тройку с 5 до 7. Поиск по отдельным абзацам дал 5 из 9, по соседним парам абзацев — 7 из 9. Когда в вопросе явно указан выпуск, оба метода дали 6 из 9 на реальной записи и 4 из 4 на учебных. E5 ответил на вопросы об извинениях и просьбе об отзыве, TF-IDF — на вопросы о признаке лояльности и низком сезоне. Основной набор по статьям дал 12 из 12 с включённой опцией E5. Эти вопросы использовались для выбора метода. Для независимой оценки нужна вторая реальная запись.

[Страница выпуска](https://doingbusiness.mave.digital/ep-32) · [RSS издателя](https://cloud.mave.digital/61514).

| Метод при указанном выпуске | Нужный отрывок в топ-3 | Ответ с нужным таймкодом | Медиана поиска на CPU | Медиана полного ответа |

### Проверка с разметкой и дополнительным семантическим поиском

Для шести пропущенных отрывков повторно распознаны короткие окна исходного аудио. После сверки в поисковый индекс добавлены термины о договорённостях в мессенджере, пути клиента, извинениях, отзывах, расписании отдыха и записи идей. Повторное распознавание сохранилось в `data/local/podcast-review.asr.jsonl`, термины — в `data/local/podcast-three-real.terms.json`. Сверка обнаружила расхождения в именах и отдельных словах, поэтому расшифровка требует ручной редакторской проверки перед публикацией.

В выпуске о сервисе Whisper поставил точку между двумя частями одного высказывания. Модель могла процитировать только первую часть про разовую реакцию и пропустить объяснение о всём пути клиента. Правка пунктуации сохраняет обе части в одном поисковом фрагменте. Время отдельных реплик осталось прежним.

С метками и TF-IDF поиск нашёл нужный интервал у 26 из 26 прежних вопросов, а ответы с ожидаемым таймкодом получены у 25 из 26. На девяти новых вопросах TF-IDF дал 6 из 9, а добавление E5 дало 9 из 9. Для восьми новых вопросов проверялись также обязательные выдержки. Для вопроса о сегменте бренда точный термин остаётся неразборчивым в двух распознаваниях. Отрывок для прослушивания сохранён в `data/local/podcast-collaborations.segment-review.wav` и начинается на 20:03 исходной записи. [Новые вопросы](../../tests/fixtures/podcast-transfer-cases.json).

При оценке использовались два выпуска Альфа-Курса и внешний контрольный выпуск Forbes. Для локального запуска с материалами Альфа-Курса используй каталог `data/local/podcast-two-alfakurs.checked.json` и его контрольную сумму. Тестовый каталог с Forbes нужен для воспроизведения сравнения.

Итоговый прогон на исправленном каталоге с дополнительным E5 прошёл 26 из 26 прежних проверок по выпуску и таймкоду и 9 из 9 новых проверок. Для ответа о международной коллаборации сработала повторная попытка после достижения лимита токенов. Отчёт — `data/local/podcast-checked.acceptance.jsonl`.

Чтобы воспроизвести исходное сравнение TF-IDF, собери тестовый каталог из трёх локальных кандидатов. Он включает внешний выпуск Forbes.

```powershell
$candidatePaths = 'data/local/podcast-servis.candidate.json',
    'data/local/podcast-collaborations.candidate.json', 'data/local/podcast-forbes-ep32.candidate.json'
$episodes = foreach ($candidatePath in $candidatePaths) {
    (Get-Content -Raw -Encoding utf8 $candidatePath | ConvertFrom-Json).episodes
}
@{version = 1; episodes = @($episodes)} | ConvertTo-Json -Depth 8 |
    Set-Content -Encoding utf8NoBOM data/local/podcast-three-real.candidate.json
$fixturePaths = 'tests/fixtures/podcast-collaborations-cases.json',
    'tests/fixtures/podcast-eval-cases.json', 'tests/fixtures/podcast-external-cases.json'
$cases = foreach ($fixturePath in $fixturePaths) {
    Get-Content -Raw -Encoding utf8 $fixturePath | ConvertFrom-Json | Where-Object episode_id -NotLike 'demo-*'
}
ConvertTo-Json -InputObject @($cases) -Depth 4 | Set-Content -Encoding utf8NoBOM data/local/podcast-three-real.scoped-cases.json
$env:AI_PODCAST_CORPUS_PATH = (Resolve-Path data/local/podcast-three-real.candidate.json).Path
$env:AI_PODCAST_CORPUS_SHA256 = (Get-FileHash $env:AI_PODCAST_CORPUS_PATH -Algorithm SHA256).Hash.ToLowerInvariant()
Remove-Item Env:AI_E5_MODEL_DIR -ErrorAction SilentlyContinue
uv run --locked --extra semantic python -m scripts.eval_podcasts --cases data/local/podcast-three-real.scoped-cases.json --output data/local/podcast-three-real.eval.jsonl --answers --name-episodes
```

Для проверки текущей конфигурации задай `AI_PODCAST_CORPUS_PATH` на размеченный каталог, пересчитай `AI_PODCAST_CORPUS_SHA256` и укажи путь к E5 в `AI_E5_MODEL_DIR`.
